# Feature Specification: API 接口文档与自助调试门户

**Feature Branch**: `001-api-docs`

**Created**: 2026-10-20

**Status**: Draft

**Input**: User description: "所有API接口需要补足swagger文档注释，服务端需要接入Swagger，Make脚本需要支持swagger文档，非prod环境需要能通过http访问接口文档"

## Clarifications

### Session 2026-10-20

- Q: 接口文档是否要把身份协议的 7 个标准端点（授权、令牌、用户信息、公钥集、撤销、自省、登出）也一起纳入？ → A: 不纳入。文档范围锁定管理 API 的 16 个端点，协议端点仅在文档页提供指向发现端点的链接。
- Q: 生成的接口描述文件应以哪个规范版本产出？ → A: OpenAPI 3.0.x，以保证接入方现有代码生成器可直接消费。
- Q: 每个接口是否要提供示例请求与示例响应数据？ → A: 全部端点提供成功响应示例，接受请求体的端点额外提供合法请求体示例，示例统一使用虚构数据，禁含真实令牌与个人数据。
- Q: 文档与源码不一致的检查，需要做为合并前的强制门禁吗？ → A: 本次不新增 CI 配置，只交付项目命令目标，并在项目文档中写明接入流水线所需的单条命令，由团队自行挂载。
- Q: dev / test 等非生产实例是否存在公网可达的部署？ → A: 不存在，仅内网与开发机回环可达。故"非 prod 零鉴权访问文档页"可接受；若将来出现公网可达的非生产实例，须先收紧为"仅内网/回环可达或要求已登录"。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 内部前端研发与后端维护者自助查阅并调试接口 (Priority: P1)

负责管理后台（admin）与账号中心（portal）的前端研发，以及接手本服务的后端维护者，在对接或排查某个管理接口时，不询问接口作者、不翻 handler 源码，直接打开浏览器访问文档页，按业务分组浏览全部管理接口，查看参数约束、成功响应结构、错误码清单，并在页面上填入参数直接发起调用，看到真实响应。

**Why this priority**: 这是本特性的核心价值。当前管理接口的契约只散落在 `AGENTS.md` 的散文表格与 handler 源码里，前端口径与后端实现容易分叉，排查线上问题时也只能靠猜。文档页可把「读契约 → 试调用 → 定位错误」压缩成一个页面内的闭环。

> 注意：第三方接入方集成 IdP 时调用的协议端点（`/oauth2/*`）不在本文档范围内，见 Assumptions。

**Independent Test**: 全新环境启动服务后，仅凭浏览器访问文档页，不参考任何源码或其它文档，完成「登录 → 创建用户 → 查询用户列表」的管理链路并得到正确响应。

**Acceptance Scenarios**:

1. **Given** 服务以非 prod 配置启动，**When** 研发在浏览器打开文档页，**Then** 页面列出管理 API 的全部端点，按标签分组，并显示每个端点的方法与路径。
2. **Given** 研发已打开某个端点的详情，**When** 展开参数区，**Then** 每个参数都标注了类型、是否必填、取值范围或格式约束，且与源码中的校验规则一致。
3. **Given** 研发想验证「创建用户」接口，**When** 在页面中填写合法请求体并提交，**Then** 页面展示真实的 HTTP 状态码与完整响应体（含 `code`、`message`、`data`、`traceId`）。
4. **Given** 研发提交了非法请求体，**When** 服务返回校验失败，**Then** 页面展示的错误码与文档中该接口列出的错误码条目可以对上，无需猜测。

---

### User Story 2 - 文档随代码演进保持一致 (Priority: P2)

后端研发修改或新增一个接口后，执行一条项目命令即可重新生成文档；若忘记重新生成，执行检查命令会立刻指出「已提交的文档与源码不一致」，并让流水线失败，从而避免文档腐化。

**Why this priority**: 没有同步机制的接口文档会在两周内变成误导性材料，比没有文档更糟。此故事保证 P1 的价值不会随时间衰减。

**Independent Test**: 在某个接口上新增一个必填请求参数但不重新生成文档，执行检查命令，观察其以失败状态退出并指出差异；随后重新生成，检查命令通过。

**Acceptance Scenarios**:

1. **Given** 研发刚完成一个接口的参数变更，**When** 执行文档生成命令，**Then** 无需手工编辑任何文档文件，生成结果即反映新参数。
2. **Given** 源码已变更但文档未重新生成，**When** 执行文档一致性检查命令，**Then** 命令以非零状态退出，并指出不一致的接口或字段。
3. **Given** 源码与文档一致，**When** 执行一致性检查命令，**Then** 命令在 1 分钟内以零状态退出且无告警。
4. **Given** 研发想在提交前本地预览，**When** 执行文档预览命令，**Then** 终端给出可点击的本地访问地址，进程保持前台运行直到被中断。

---

### User Story 3 - 生产环境不暴露接口文档 (Priority: P3)

安全或运维人员在生产环境核查对外暴露面，确认接口文档页面与规范文件均不可访问，且无法通过任何默认配置意外打开。

**Why this priority**: 接口文档等价于攻击面地图，包含全部参数名、错误分支与内部枚举值。生产环境暴露属于信息泄露，必须在设计上默认关闭，而不是靠运维记得改配置。

**Independent Test**: 以 prod 配置启动服务，逐一请求文档页路径与规范文件路径，断言全部返回与「路径不存在」一致的统一响应，且响应体不泄露该路径被有意禁用。

**Acceptance Scenarios**:

1. **Given** 服务以 prod 配置启动，**When** 请求文档页路径，**Then** 返回 404 与统一错误响应体，响应内容与访问任意不存在的路径完全一致。
2. **Given** 服务以 prod 配置启动，**When** 请求规范文件路径（含常见变体路径），**Then** 全部返回 404，无任一返回文件内容。
3. **Given** 服务以 dev 配置启动，**When** 请求同样的文档路径，**Then** 正常返回文档页，说明该差异由运行环境决定而非代码分支散落判断。
4. **Given** prod 配置下文档被关闭，**When** 业务接口正常调用，**Then** 行为与本特性上线前完全一致，无性能或兼容性回归。

---

### Edge Cases

- **接口已改、注释未改**：方法或路径变更后若注释未同步，一致性检查必须失败，不能因为「文件存在」而放行。
- **同一数据结构被多个接口复用**：必须在文档中以同一份定义被引用，避免出现两份结构相同但字段描述互相矛盾的副本。
- **未被显式声明的失败路径**：运行时 panic 触发的 500、限流触发的 429、未匹配路由触发的 404，都必须能在文档中找到对应条目，不能让调用方遇到「文档里没有的错误码」。
- **文档路径与业务路径冲突**：文档必须占用固定的保留前缀，未来业务接口不得与之重叠；命名冲突时以文档让步（换前缀）而非业务接口让步。
- **内网/离线环境**：文档页在无外网访问的机器上必须完整可用，不得依赖外部 CDN 加载脚本或样式。
- **文档页与登录态的关系**：非 prod 环境访问文档页本身不需要登录，但通过页面调试受保护接口时，仍受该接口原有鉴权约束，文档不得成为绕过鉴权的通道。
- **审计噪音**：文档页自身的加载与静态资源请求不应被记为业务操作审计事件，否则会淹没真实操作记录。

## Requirements *(mandatory)*

### Functional Requirements

**覆盖范围**

- **FR-001**: 系统 MUST 为管理 API（`:8081`，`/api/v1/*`）对外暴露的每一个端点提供文档条目，当前基线为 16 个端点，覆盖方法、路径、用途摘要、所属业务分组。
- **FR-002**: 文档 MUST 标注每个端点的鉴权要求，区分「公开」「需登录」「需管理员」三类，并与实际中间件挂载一致。
- **FR-003**: 文档 MUST 覆盖全局鉴权载体（会话 Cookie）的说明，包括 Cookie 名称、有效期语义、以及在文档页发起调试调用时该凭证如何被携带。

**内容完整性**

- **FR-004**: 每个端点 MUST 记录全部入参，按路径参数、查询参数、请求体三区分别列出，每项含名称、类型、是否必填、取值范围或格式约束、默认值。
- **FR-005**: 每个端点 MUST 记录成功响应的状态码与完整响应体结构，字段级说明需与统一响应封装一致。
- **FR-006**: 每个端点 MUST 记录其可能返回的全部错误码，每项含 HTTP 状态码、业务码、触发条件；至少覆盖校验失败、未认证、无权限、资源不存在、冲突、限流六类中适用于该端点的部分。
- **FR-007**: 统一响应封装（`code` / `message` / `data` / `traceId`）与统一错误结构 MUST 以可复用定义的形式记录一次，各端点引用同一份定义，禁止逐接口重复描述。
- **FR-008**: 分页类端点 MUST 记录分页参数的默认值与上限，以及分页响应的字段含义。
- **FR-009**: 文档 MUST 记录运行时产生的通用失败路径，包括未匹配路由与方法不允许返回的统一 404 结构、限流返回的 429 结构。这类失败不属于任何单个端点，应记录在文档的全局说明中（而非逐端点重复），且全局说明须给出这两个结构的真实响应体样例。

**生成与维护**

- **FR-010**: 文档内容 MUST 由源码中的结构化注释生成，仓库 MUST NOT 出现需要人工逐条维护的接口描述文件。
- **FR-011**: 项目命令集 MUST 提供三个可独立执行的目标：生成文档、校验文档与源码一致性、启动本地预览。
- **FR-012**: 一致性校验目标 MUST 在文档滞后于源码时以非零状态退出，并在输出中定位到具体端点或字段；校验耗时可接受上限为 1 分钟。
- **FR-013**: 生成产物 MUST 纳入版本控制，使文档变更可与代码变更在同一处评审。
- **FR-014**: 生成与校验过程 MUST NOT 要求连接数据库、Redis 或任何外部服务，可在离线环境下完成。

**环境隔离**

- **FR-015**: 当运行环境为非 prod（`APP_ENV` 取 `prod` 以外的任意值）时，文档页与规范文件 MUST 可通过 HTTP 直接访问，无需登录。
- **FR-016**: 当运行环境为 prod 时，文档页与规范文件的路由 MUST NOT 被注册，请求返回的响应必须与该路径从未存在时完全一致，不得暴露「已禁用」这一信息。
- **FR-017**: prod 下的文档关闭 MUST 由运行环境单一配置项决定，禁止在多个位置重复判断环境，避免出现遗漏分支。
- **FR-018**: 文档路由 MUST 挂载在管理 API 端口上，不新增监听端口。
- **FR-019**: 文档页 MUST 在页面上显示当前运行环境标识与服务版本，使研发能确认自己所调用的实例。
- **FR-020**: 文档页的加载 MUST NOT 依赖外部网络资源，内网与离线机器上功能完整。

**文档契约与交付**

- **FR-021**: 生成的接口描述文件 MUST 以 OpenAPI 3.0.x 版本产出，可被标准 OpenAPI 工具链（客户端代码生成器、文档 UI、规范校验器）直接消费，无需降级转换。
- **FR-022**: 每个端点 MUST 提供成功响应的示例值；接受请求体的端点 MUST 额外提供一份可直接提交的合法请求体示例。全部示例 MUST 使用虚构数据（如 `zhangsan`、`01J9Z...` 形态的标识），MUST NOT 出现真实令牌、密钥、真实手机号或个人数据。
- **FR-023**: 三个项目命令目标及「在流水线中调用一致性检查」的单条命令 MUST 写入项目既有开发文档（`README.md` 开发流程段落），使团队无需口头传递即可自行挂载；本次范围 MUST NOT 新增 CI 流水线配置文件。

### Key Entities *(include if feature involves data)*

- **接口条目（Operation）**：描述一个「方法 + 路径」组合的可对外契约，含摘要、业务分组、鉴权要求、入参集合、响应集合、错误码集合。与管理 API 的端点一一对应。
- **参数（Parameter）**：描述单个入参，含名称、位置（路径/查询/请求体）、数据类型、必填性、约束（长度、正则、枚举、数值区间）、默认值、说明。
- **数据结构定义（Schema）**：描述可复用对象结构，含字段清单及各字段的参数级约束。被接口条目通过引用复用，不重复定义。
- **错误码条目（Error Code）**：描述一类失败，含 HTTP 状态码、业务码、触发条件、面向调用方的处置建议。与统一错误枚举一一对应。
- **鉴权等级（Auth Level）**：公开 / 需登录 / 需管理员，描述端点的访问门槛，决定文档页调试时是否需要预先登录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理 API 的 16 个端点在文档页全部可见，覆盖率 100%，无端点仅存在于代码中。
- **SC-002**: 首次接触本项目的研发在无人协助下，10 分钟内完成一次「登录 → 创建用户 → 查询用户列表」的管理链路调用并得到正确响应。**测量方式**：1 名未参与本特性的研发，从打开文档页开始计时，首次拿到正确响应即停止；连续 2 人达标视为通过。
- **SC-003**: 任一接口新增必填参数后，一致性校验在 1 分钟内报出不一致并使检查命令失败，漏报率为 0。
- **SC-004**: 在 prod 配置下抽查文档页与规范文件的全部已知访问路径，404 命中率为 100%，且响应体除 `traceId` 外与随机不存在路径完全一致。
- **SC-005**: 单次文档生成在不联网、不启动数据库的条件下 30 秒内完成，无需任何人工编辑步骤。
- **SC-006**: 覆盖本特性上线后新增接口的场景：研发**不需要手工编辑任何文档内容**（产物由命令生成、不额外声明逐接口包装类型），且生成后一致性校验通过。判定方式：新增端点时 `git status` 的改动只允许出现三类文件——该 handler 文件（注解）、`internal/api/router.go`（路由注册）、`internal/api/docs/openapi.json`（`make docs` 产物）；改完后 `make docs-check` 退出码为 0。**注意**：`make docs-check` 在产物未重新生成时**必须**失败（FR-012），这正是本判据区分"忘记生成"与"零手工维护"的关键。

## Assumptions

- **文档范围**：仅覆盖管理 API（`:8081`）的 16 个端点。OIDC 协议端点（`:8080`，授权、令牌、用户信息、JWKS、撤销、自省、登出等 7 个）由 OpenID Connect 规范定义，其字段由协议库生成且不允许改写，经澄清确认不纳入本文档范围；文档页仅提供指向发现端点（`.well-known/openid-configuration`）的链接，供接入方跳转查阅。
- **访问入口**：文档页与规范文件随管理 API 同端口（`:8081`）提供，使用固定保留前缀，不新增端口，也不复用协议层端口。
- **环境判定**：以单个环境变量 `APP_ENV` 判定，值为 `prod` 即生产，其余值（如 `dev`、`test`）均视为非生产。
- **网络可达性（已与负责人确认）**：dev / test 等非生产实例**不存在公网可达的部署**，仅在内网与开发机回环地址访问。因此"非 prod 零鉴权访问文档页"不构成信息泄露面；若将来出现公网可达的非生产实例，必须先把本条改为"仅内网/回环可达或要求已登录"，再放开该实例的文档路由。
- **服务对象**：本文档面向内部前端研发与后端维护者（管理 API 的消费方），不面向第三方接入方；接入方的协议接口以其 discovery 文档为准。
- **产物归属**：生成的规范文件纳入版本控制，作为评审对象；文档页前端资源随二进制或静态目录提供，不依赖外部 CDN。
- **语言与术语**：摘要与说明使用中文，技术标识符（路径、字段名、业务码）保持英文原样，与 `AGENTS.md` 保持一致。
- **契约稳定性**：本特性不新增、不删除、不改变任何业务端点的行为与字段，仅补齐文档与访问入口；现有接口的响应结构不受影响。
- **调试前置条件**：文档页调试受保护接口时，浏览器需已持有有效会话 Cookie；文档本身不提供登录代理，也不放宽鉴权。
- **审计边界**：文档页静态资源加载不产生认证或业务审计事件，避免污染审计日志。
- **既有规范约束**：本特性不改变端口划分、分层结构与凭证不出服务端等既有约束，文档不得在响应示例中展示真实令牌或密钥。
