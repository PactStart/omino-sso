## Executive Summary

规格与计划在**可验证性**上明显强于一般文档类特性（23 条 FR 全部带判定口径，6 条 SC 均有对照的验收场景），工程侧的依赖选型也有实证依据（swag 只产 2.0、需 openapi2conv 转换，这条判断经核验成立）。但存在三处必须先修的硬伤：

1. **价值论证的角色错位**——US1 的服务对象写成"接入方研发"，而文档范围恰恰排除了接入方真正调用的 `/oauth2/*`（澄清 Q1 已定）。管理 API 的读者是内部前端与维护者。这不是措辞问题，而是"为什么做这件事"的论证基础。
2. **一条不可达成的验收判据**——多处要求"改造前后响应体**逐字节**一致"。`gin.H` 是 map，`encoding/json` 对 map 键**按字典序排序**，而结构体按字段声明序输出；键序天然不同，逐字节比对必然失败，除非把字段强行按字母序声明（脆且无意义）。
3. **"离线可生成"存在反例**——`make docs` 计划用 `go run github.com/swaggo/swag/cmd/swag@<ver>`；冷缓存机器上该命令必须访问模块代理，与 FR-014"不依赖外部服务、可离线完成"直接冲突。

三处都是**低成本可修**（改措辞、换判据、把 CLI 固定进 `go.mod`），不构成推倒重来。另有 11 条建议与 2 个需你拍板的问题，其中"swagger-ui 是否携带会话 Cookie"直接决定 SC-002 能否达标，建议在写代码前用半小时 spike 验证。

## Engineering Lens Findings 🔬

### Architecture Soundness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E1 | 💡 | **`make build` 不校验文档新鲜度**，导致"源码改了、二进制里嵌入的还是旧文档"可以一路发布。漂移检测只在有人记得跑 `make docs-check` 时生效——这正是本特性要防的失败模式 | 让 `build` 依赖 `docs-check`（≤1 min，纯本地），或至少在 `build` 中输出醒目警告。前者更彻底，且不违反"不加 CI 配置"的既有决策 |

### Failure Mode Analysis

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E2 | 💡 | **文档页会被全局限流波及**。`router.go:38` 的 `RateLimit(api)` 挂在 `r.Use`，`/docs/*` 也在其内；一个 swagger-ui 首屏约 10+ 个静态资源请求，演示或压测时可能触发 429，表现为"文档打不开" | 对 `/docs/*` 走静态分支：在限流中间件里按前缀跳过，或为文档路由单独放行；同时在 `contracts/doc-endpoints.md` §3 把"不挂限流"写成明确条款（当前只写了"不挂独立限流器"，含糊） |
| E3 | 💡 | **Redis 不可用时文档页是否可用未定义**。文档页本身不需要 Redis，但限流中间件依赖它；若中间件 fail-closed，则 Redis 抖动时文档页 503，与"运维故障时最需要查文档"的场景正相反 | 在 `quickstart.md` 增加一个"停掉 Redis 后访问 `/docs/`"的观察项，并在计划中明确限流中间件对该路径的行为；若 fail-closed 则采纳 E2 的前缀跳过方案，一并解决 |

### Security & Privacy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E4 | 🤔 | **"非 prod 即可无鉴权访问"的前提未被确认**。若 dev/test 实例存在公网可达的部署（演示环境、外包联调环境），文档页会把完整管理 API 面、参数名、错误码与示例全部公开，属实质信息泄露 | 需你确认：dev/test 是否可能被公网访问？若"是"，则应改为"非 prod 且仅内网/回环地址可访问"，或复用 admin 会话校验 |
| E5 | 💡 | **文档本身被打进 prod 二进制**。`//go:embed` 使 `openapi.json` 与 swagger-ui 资源存在于生产产物中，虽不对外路由，但拿到二进制即可提取完整接口面 | 接受这一残余风险（收益是构建简单），但在 `plan.md` 的复杂度登记中显式写一句"prod 二进制含文档资源但不可路由"，避免日后被当成疏漏 |

### Performance & Scalability

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E6 | 💡 | **二进制体积增加未评估**。`swaggo/files` 内嵌 swagger-ui（含字体）通常带来数 MB 增长，对容器镜像有实际影响，而规模一节只估了 JSON 大小 | 在 `data-model.md` §8 补一行"预计二进制 +3~5MB（待实测）"，并在 `quickstart.md` 场景 3 记录 `ls -lh bin/sso` 的前后对比 |

### Testing Strategy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E7 | 🎯 | **"逐字节一致"判据不可达成**。`contracts/annotation-conventions.md` §4 与 `plan.md` 均要求具名化改造前后响应体**逐字节**对比。事实是：`gin.H` 是 `map[string]any`，`encoding/json` 序列化 map 时**按键字典序**输出；结构体按**字段声明序**输出。二者键序天然不同，逐字节比对必然失败；若为通过而把字段按字母序声明，则破坏可读性且新增变量 | 把判据改为**语义等价**：`json.Unmarshal` 到 `map[string]any` 后 `reflect.DeepEqual`，并额外断言**键集合完全相同**（含 `null` 值键，如 `mfaTicket`、`expiresAt`）。同步修正 `plan.md`、`contracts/annotation-conventions.md` §4 的"逐字节"表述为"语义等价 + 键集合相同" |
| E8 | 💡 | **缺少 golden 测试的强制要求**。计划只说"用测试或手工 curl 比对"，未要求把 8 处 `gin.H` 的现有输出固化为测试夹具；手工 curl 无法防止后续回归 | 在任务分解中明确：为 8 处响应各写一个不依赖 DB 的单测，构造 `gin.H{...}` 与对应 `dto.X{...}` 同值实例，`DeepEqual` 二者序列化后的 map；改造后删除 `gin.H` 分支，测试改为对结构体断言 |

### Operational Readiness

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E9 | 🎯 | **"离线生成"存在反例**。`plan.md`/`research.md` 拟定 `make docs` 执行 `go run github.com/swaggo/swag/cmd/swag@<version>`。带 `@version` 的 `go run` 在冷缓存/无网环境下必须访问模块代理，直接与 FR-014"不连接外部服务、可离线完成"冲突；本项目的部署环境是内网，这条不是理论问题 | 把 swag CLI 固定进 `go.mod`（`tools.go` + `//go:build tools` 的标准做法），`make docs` 改为 `go run github.com/swaggo/swag/cmd/swag`（不带 `@version`，走已锁定模块）。这样 `go mod download` 一次后即永久离线可用，同时版本被 `go.sum` 锁定 |
| E10 | 💡 | **回滚与发布策略未提**。特性本身是纯增量（新增路由与文件），回滚即 revert，但 `openapi.json` 入库后若某次生成的产物被误提交为不一致状态，回滚粒度不清 | 在 `plan.md` 补一句"回滚 = 单次 revert；`openapi.json` 与其对应的注解改动必须在同一提交内，禁止分开提交"，避免出现"代码回了文档没回" |

### Dependencies & Integration

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E11 | 💡 | **依赖的许可与维护状态未登记**。T001 要求把版本写进 `AGENTS.md` §2，但没要求记录许可证（MIT/Apache-2.0）与维护活跃度；`swaggo/swag` 的 OAS3 提案挂了六年，其维护节奏值得留档 | T001 增加两列：`license` 与"维护状态/最近提交年份"；对 `kin-openapi` 的 `openapi2conv` 子包特别注明"仅做格式转换，不承担语义扩展" |
