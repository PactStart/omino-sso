## Clarifications

### Session 2026-10-24

- Q: 本地端到端验证用什么方式驱动三个示例，示例进程由谁启动？ → A: 无头 HTTP 驱动（无浏览器），验证命令自行拉起三个示例进程并在结束时关闭，与仓库既有端到端脚本同构。
- Q: 三个示例在本地各用哪个端口？ → A: 各占一个互不冲突的固定端口（8000 / 8001 / 8002），回调按端口分别注册；文档里三个示例同用 8000 属单示例场景，不再沿用。
- Q: 浏览器打开示例时，用户看到的是页面还是 JSON 接口返回？ → A: 做成一页可点击的演示界面（含登录/登出与用户信息展示，带基本样式），四个契约端点仍返回 JSON。
- Q: 示例要不要演示 refresh_token 的轮换续期？ → A: 要。保存 refresh_token，访问令牌失效时单飞刷新并轮换，刷新失败才回落重新授权。
- Q: `docs/integration-guide.md` §9 已有三份完整代码，与 `examples/` 谁为准？ → A: `examples/` 为接入代码的唯一权威；文档 §9 收敛为「指向示例的索引 + 差异说明」，该文档改动是本特性交付物之一。
- Q: 端到端脚本用哪个账号登录（避免触发失败锁定）？ → A: 用专用示例账号：不存在则创建、存在则复用；与演示账号 `zhangsan` 解耦，且脚本对同一账号登录失败立即中止、不重试。
- Q: 示例依赖是否也锁精确版本？ → A: 锁。各语言清单写精确版本（Go 用 `go get` 解析后回写、pip 用 `==`、Maven 用固定 parent 版本），README 记录已验证版本矩阵。
- Q: 演示环境用 `localhost` 还是 `*.lvh.me` 子域？ → A: 保持 `localhost`；cookie 冲突风险由「示例会话 cookie 必须带语言前缀」消除，不引入 DNS/代理。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三种语言各自跑通登录闭环（Priority: P1）

接入方研发拿到一个语言对应的示例工程，按说明填好四个环境变量、启动进程，在浏览器里从示例自己的「登录」入口出发，经统一身份登录后回到示例页面，看到「我是谁」的信息（用户唯一标识、登录名、显示名、角色、认证方式）。整个过程不需要写任何协议代码。

**Why this priority**：这是本特性的核心价值——把接入文档从「读得懂」变成「跑得通」。三个语言各自独立成立，任一语言先完成即可验证文档正确性。

**Independent Test**：只启动统一身份与本语言示例，走完「访问受保护页 → 跳转登录 → 回到示例 → 用户信息可见」，即可判定该语言示例可用。

**Acceptance Scenarios**：

1. **Given** 统一身份已在本地运行且已注册该示例的回调地址，**When** 用户打开示例的演示首页并点击「登录」，**Then** 浏览器被 302 到统一身份的登录页，而非示例自己渲染登录表单。
2. **Given** 用户在统一身份登录页完成账号密码登录，**When** 回调落到示例的 `/callback`，**Then** 示例完成令牌交换与身份校验并建立自己的本地会话，演示页面展示当前用户信息（唯一标识、登录名、显示名、角色、认证方式），且页面有可见的「登出」入口。
3. **Given** 示例已建立本地会话，**When** 刷新或再次访问 `/api/me`，**Then** 返回 200 且用户信息不变，且不产生新的授权跳转。
4. **Given** 示例未建立本地会话，**When** 直接访问 `/api/me`，**Then** 返回 401（明确「未登录」），而不是重定向或空 200。
5. **Given** 用户在示例点击「登出」，**When** 浏览器完成跳转，**Then** 示例本地会话被清除、统一身份的登录会话也被清除，再次打开示例受保护页面必须重新登录。
6. **Given** 授权流程中回调地址或客户端凭据与注册值不一致，**When** 令牌交换失败，**Then** 示例返回可诊断的错误（含失败环节与统一身份返回的错误码），不吞掉错误也不无限重试。
7. **Given** 示例的访问令牌已过期且本地保存了可用的 refresh_token，**When** 用户继续访问演示页面，**Then** 示例完成一次刷新并继续展示同一用户，期间不出现登录页；若刷新被统一身份拒绝（如令牌族已被吊销），则回落到重新授权，而不是停在空白页或无限重试。

### User Story 2 - 一条命令完成本地端到端验证（Priority: P1）

维护者在本地已启动统一身份的前提下，执行一条命令，自动把三个示例串起来验证：三示例分别完成登录、跨示例免登录、登出后全部失效；命令结束时以退出码与逐项断言说明结果。

**Why this priority**：没有可重复的端到端验证，「三个示例能跑」只是一次性人工结论；文档与依赖很快会漂移。

**Independent Test**：在干净的本地环境执行该命令，观察逐项断言与退出码即可判定；不需要人工点浏览器。

**Acceptance Scenarios**：

1. **Given** 统一身份已启动，**When** 执行端到端命令，**Then** 三个示例被逐个驱动完成授权码登录，每项断言都有明确的通过/失败输出。
2. **Given** 用户已通过示例 A 完成登录（同一浏览器会话），**When** 访问示例 B 的登录入口，**Then** 不再出现登录页、直接完成授权并回到 B 的 `/api/me` 200——即单点登录在接入方之间生效。
3. **Given** 三个示例都建立了本地会话，**When** 触发登出并清空统一身份会话，**Then** 三个示例的 `/api/me` 全部返回 401。
4. **Given** 上一次执行已在本地数据库留下示例的客户端注册与测试数据，**When** 再次执行同一条命令，**Then** 依然全绿——验证过程必须可重复，不得依赖「先手工清理」。
5. **Given** 某个示例无法被拉起（端口被占用、构建或依赖准备失败），**When** 执行端到端命令，**Then** 命令以非零退出码失败并指出是哪个示例、哪个环节，不静默跳过该项断言。

### User Story 3 - 三语言横向对照（Priority: P2）

研发要评估「换一门语言重写接入」的成本时，能在三个示例之间逐项对照：暴露的端点、环境变量名、失败提示、发起登录与取用户信息的位置一一对应。

**Why this priority**：示例的长期价值是「可比」。若三者各写一套命名与路由，对照成本会抵消示例的意义；但它不阻塞单个示例可用性，故排在 P1 之后。

**Independent Test**：对照三个示例的端点清单与环境变量清单，逐项应为同名同义；用同一份操作步骤分别操作三者，行为一致。

**Acceptance Scenarios**：

1. **Given** 三个示例工程，**When** 核对对外路由，**Then** 除演示首页（`/`）外，均只暴露 `/login`、`/callback`、`/api/me`、`/logout` 四个契约端点，且路径完全一致。
2. **Given** 三个示例工程，**When** 核对启动配置，**Then** 使用同一组环境变量名（统一身份的 issuer、客户端标识、客户端密钥、回调地址、会话密钥），缺任意必需项时都在启动阶段失败并打印缺失项名称。
3. **Given** 同一份操作说明，**When** 依次对三个示例执行，**Then** 操作步骤与预期结果完全一致，无需语言专属的额外步骤（注册回调地址除外，见 Assumptions）。

---

### Edge Cases

- **端口冲突**：三个示例默认端口若被占用，示例应在启动时明确报错而非静默换端口（换端口会使已注册回调失效）。
- **统一身份未启动**：示例启动时的元数据发现失败应给出「连不上 issuer」的可诊断信息，而不是等到用户点击登录才失败。
- **回调地址逐字符不匹配**：统一身份以授权码错误拒绝时，示例需把该错误码原样暴露，便于对照接入文档的排错表定位。
- **重复登录**：用户已有统一身份会话时再次点登录，应直接回到示例，不再要求输入密码。
- **并发刷新**：同一会话多个并发请求同时遇到访问令牌过期时，只能发出一次刷新请求，其余请求等待同一结果；重复使用旧 refresh_token 会触发整族吊销、把用户强制重登。
- **刷新被拒**：refresh_token 过期或已被吊销时，示例必须回落到重新授权流程，并清掉本地失效令牌，不得继续用旧令牌反复重试。
- **userinfo 不可达**：统一身份的用户信息端点超时或 5xx 时，示例页面仍须可用（身份取本地令牌、应用内角色为空并提示降级），不得返回 5xx。
- **cookie 碰撞**：三个示例与统一身份共享 `localhost` 这一 cookie 域（端口不参与隔离），示例会话 cookie 必须带语言前缀；若观察到统一身份的 `sid` 值被示例改写，即为缺陷。
- **脚本失败重试边界**：对同一账号的登录失败必须立即中止（失败计数会累加，重试可能锁死账号），只允许对网络类瞬时错误做一次幂等重试。
- **客户端密钥泄露面**：示例的密钥只能出现在服务端进程环境里，不得出现在页面、浏览器可读存储或仓库文件中。
- **依赖获取失败**：离线或依赖源不可达时，构建/启动应失败并指出缺失依赖，不得降级为无校验的「假登录」。
- **残留数据**：上一次验证留下的客户端注册、测试会话不影响下一次执行（可重复执行）。
- **示例对外暴露面**：示例仅用于本地演示，文档需说明其不得直接部署到公网（无 TLS、无加固）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 仓库根目录必须新增 `examples/` 目录，内含三个**可独立构建、独立运行**的示例工程，分别用 Go、Java、Python 编写；三者互不依赖，可单独启动。
- **FR-002**: 每个示例必须暴露完全一致的四个端点：发起登录、回调、当前用户、登出；路径三语言相同，便于横向对照。
- **FR-003**: 授权流程必须使用文档规定的标准授权码 + PKCE（仅 S256），并校验 `state` 与 `nonce`；不得实现 implicit、password 或设备码等文档明确不支持的方式。
- **FR-004**: 令牌交换必须由示例的服务端完成，且客户端凭据只通过文档规定的客户端认证方式传递；浏览器侧不得接触任何令牌或客户端密钥。
- **FR-005**: 身份校验必须使用该语言生态的成熟 OIDC 实现（即接入文档 §9 指定的组合），不得自研 JWT 验签、JWKS 缓存或授权状态机。
- **FR-006**: 示例必须能读取并使用文档列出的标准与自定义声明（唯一标识、登录名、显示名、邮箱、租户、部门、角色、认证方式），并以统一字段名对外输出。
- **FR-007**: 示例必须支持从 `userinfo` 读取仅在该端点下发的应用内角色与权限，并在当前用户接口中体现（即使是空数组）；当 `userinfo` 不可达时**必须降级**：用本地会话里的令牌声明继续返回用户信息、`appRoles`/`permissions` 返回空数组并标注降级原因，不得把 IdP 抖动放大成 5xx。
- **FR-008**: 登出必须同时做到：清除示例本地会话、引导浏览器清除统一身份会话；登出后示例的当前用户接口必须返回未登录。
- **FR-009**: 三个示例的全部可变配置必须来自环境变量（统一身份地址、客户端标识、客户端密钥、回调地址、会话密钥）；仓库内不得出现任何真实密钥。
- **FR-010**: 缺少任一必需环境变量时，示例必须在启动阶段失败并打印缺失项名称；不得以默认值静默运行。
- **FR-011**: 必须提供一条可重复执行的本地端到端验证入口，**无需浏览器**：由该入口自行拉起三个示例进程（结束时负责关闭），自动完成：为三个示例准备可用的客户端注册 → 驱动三示例登录 → 断言跨示例免登录 → 登出后断言三示例均未登录。
- **FR-012**: 端到端验证必须幂等：允许在本地数据库留下注册与测试数据，但重复执行不得因残留数据失败；同时不得破坏统一身份既有演示数据——脚本使用**专用示例账号**（不存在则创建、存在则复用），与演示账号解耦；对同一账号的登录一旦失败立即中止、不重试（避免触发失败计数与锁定），也不修改内置客户端的回调白名单。
- **FR-013**: 端到端验证必须在失败时给出非零退出码与可定位的输出（哪个示例、哪个断言、实际值），不得静默跳过。
- **FR-014**: 必须在 `examples/` 下提供**唯一一份**说明文档（覆盖三语言的环境变量、注册回调地址、运行命令、验证命令与常见报错对照），不新增仓库根级文档。
- **FR-015**: 本特性**不得修改统一身份服务的实现**（协议层、管理 API、数据库结构、既有前端）。若验证中发现必须由服务端改造才能接入，按接入文档「需要 IdP 侧改造时」一节登记为后续独立特性，不在本特性内实施。
- **FR-016**: 示例工程与端到端验证入口不得进入服务端镜像或生产构建产物，且新增内容不得使仓库既有的构建、测试、检查与文档一致性门禁失败（示例自身的依赖与产物需与主站隔离）。
- **FR-017**: 三个示例必须默认监听互不冲突的固定端口（8000 / 8001 / 8002），使三者可同时运行；端口可由环境变量覆盖，但不得自动换端口（换端口会让已注册回调失效，也无法复现验证结果）。
- **FR-018**: 每个示例必须提供一个可交互的演示界面：未登录时显示「登录」入口，登录后展示当前用户信息与「登出」入口；界面由该语言生态的模板机制渲染并带基本样式，且不得为示例引入与该语言无关的前端构建链（不新增前端工程或打包步骤）；四个契约端点的响应仍为 JSON，不被页面渲染逻辑改写。
- **FR-019**: 三个示例必须保存 refresh_token 并在访问令牌失效时执行**单飞刷新**（并发请求只触发一次），用轮换后的新令牌覆盖旧值；刷新被拒时必须清掉本地失效令牌并回落到重新授权，不得静默继续或指数重试。
- **FR-020**: `examples/` 必须是接入代码的**唯一权威**：`docs/integration-guide.md` 的三语言完整示例收敛为「指向 `examples/` 的索引 + 与文档既有约定不一致处的差异说明」，不得保留第二份可复制代码；该文档改动是本特性的交付物。
- **FR-021**: 示例的会话 cookie 名必须带语言前缀（`sid_go` / `sid_java` / `sid_py`），**不得**使用 `sid`；三个示例与统一身份同处 `localhost` 且 HTTP cookie 不按端口隔离，重名会互相覆盖。任何示例操作都不得改写统一身份的 `sid` cookie。
- **FR-022**: 示例必须在演示页页脚与说明文档中标注「仅本地演示」，并点明生产必须改的三处：登出改为 POST + CSRF 防护、启用 HTTPS 与 `Secure` cookie、会话移出进程内存。
- **FR-023**: 示例的依赖版本必须写**精确版本**（Go 回写 `go.mod`、Python 用 `==`、Java 固定 parent 版本），并在说明文档记录「已验证版本矩阵」（语言版本 + 依赖版本 + 验证日期）。
- **FR-024**: 演示页必须展示**非敏感**的会话状态：访问令牌剩余有效期与「上次刷新时间」，以便人工点验时能确认刷新确实发生过；不得展示令牌本身或任何可重放材料。
- **FR-025**: 示例必须提供**仅调试用途**的故障注入入口（不改代码即可把 `userinfo` 指向不可达地址），使「IdP 角色接口不可用时的降级」可被端到端自动验证，而不是永远跳过。

### Key Entities *(include if feature involves data)*

- **示例应用（Example App）**：一个语言实现的最小接入方，含四个端点、一组环境变量配置、一个本地会话存储；三份实现语义等价。
- **客户端注册（Client Registration）**：示例在统一身份侧的身份，含客户端标识、密钥、回调地址白名单、可用授权方式与范围；端到端验证需为其准备或复用它。
- **端到端用例（E2E Case）**：一条「示例 × 环节 × 期望」的断言，覆盖登录、跨示例免登录、登出失效、失败可诊断。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 只按 `examples/` 的说明操作，三种语言各自从零到 `/api/me` 返回 200；该时长由端到端脚本记录的「示例启动→首次 200」耗时量化，并在说明文档固定一行「实测用时」。
- **SC-002**: 一条命令完成三示例端到端验证，全部断言通过且退出码为 0；**首次执行（含依赖准备与 Maven/pip 冷缓存）≤ 10 分钟，后续执行 ≤ 3 分钟**。
- **SC-003**: 跨示例单点登录 3/3 组合全部通过：登录任一示例后，其余 2 个示例的 `/api/me` 均 200 且 `sub` 与首个示例相同。
- **SC-004**: 登出后失效率 100%：三个示例的当前用户接口全部返回未登录，且重新访问必须重新登录。
- **SC-005**: 仓库中明文密钥为 0：示例配置中不出现任何真实客户端密钥或会话密钥。
- **SC-006**: 三语言一致性可核：端点清单与环境变量清单 100% 同名同义，说明文档中的对照表与实测行为一致；文档记录的「已验证版本矩阵」与实际依赖清单逐项一致。
- **SC-007**: 端到端验证连续执行两次均成功，证明可重复（幂等）。
- **SC-008**: 三个示例各完成至少一次真实刷新：旧 refresh_token 失效、新令牌可用、用户身份不变；刷新被拒时能回落到重新授权（示例不出现死循环或空白页）。
- **SC-009**: 统一身份的 `userinfo` 不可用时，示例的用户页仍返回 200（身份信息来自本地令牌、应用内角色为空并标注降级），不出现 5xx；该路径由故障注入在端到端中**实际执行**，不得以跳过代替。
- **SC-010**: 三个示例写入浏览器的会话 cookie 名恰为 `sid_go` / `sid_java` / `sid_py`，三者互不相同，且均不为 `sid`（cookie 前缀的正向断言，可与 A16 对应）。

## Assumptions

- **本地统一身份形态**：使用仓库既有的本地开发形态（协议端点在 `localhost:8080`，`APP_ENV` 非生产），因此允许 `http://localhost` 形态的回调地址与本地明文传输；这与现有演示门户的回调约定一致。
- **验证账号**：端到端验证使用**专用示例账号**（脚本首次运行时创建、之后复用），不复用演示账号 `zhangsan`——因为服务端有登录失败计数与锁定，脚本对同一账号要登录多次，复用会把演示账号锁死的风险转嫁给用户。该账号不绑多因素认证；若被绑定，脚本以非零码明确提示而不是静默失败。
- **端口分配**：三个示例默认各占一个互不冲突的固定端口（8000 / 8001 / 8002），可通过环境变量覆盖；端口变化后需同步注册回调地址。接入文档中「三个示例都用 8000」只是单示例演示口径，本特性不沿用。
- **数据残留可接受**：按用户明确说明，本地数据库的改动无需还原；因此验证入口采取「幂等复用」而非「事后清理」策略，且不触碰既有演示账号密码与内置客户端回调。
- **演示界面的实现边界**：选定「一页可点击界面」后，界面用各语言生态的模板渲染 + 少量静态样式实现，不为示例再引入前端工程（Node 工具链、打包器）。理由：本特性演示的是**接入协议**，加第二套构建链会把「按说明跑起来」的前置条件显著变重，也与项目宪法「不顺手扩大技术面」的取向相悖。
- **不做的事**：示例不做容器化、不做生产部署、不做多租户或权限模型演示、不引入接入文档未提及的协议扩展（如动态注册、后置登出回跳）。
- **说明文档的唯一例外**：项目宪法要求「不生成 README 等文档，除非任务明确要求」。本特性需在 `examples/` 下提供一份说明，理由是示例的可运行性依赖环境变量与回调注册等前置条件，缺此说明示例即不可用；该说明限定为一份、位于 `examples/` 内，不扩写根级文档。
- **语言与运行时**：按接入文档已经冻结的三套技术组合实现（Java 侧为 Spring 生态、Python 侧为 Authlib 生态、Go 侧为 `go-oidc` + `x/oauth2`）；本地需具备对应语言运行时与包管理器，版本不满足时由实现阶段记录最小可用升级。
- **回调地址差异**：Java 框架的默认回调路径与另外两者不同，本特性为达成「横向对照」将其对齐为同一路径；这属于示例内配置选择，不改变统一身份的匹配规则（仍为逐字符精确匹配），且必须在说明文档中标注。
- **演示域名与 cookie 隔离**：演示环境保持 `localhost`（不引入 `*.lvh.me` 等子域），因为 HTTP cookie 不按端口隔离，三个示例与统一身份共享 `localhost` 这一 cookie 域；冲突风险由 FR-021 的「会话 cookie 必须带语言前缀」消除，说明文档需解释这一约束的由来，避免复制者误以为是命名风格。
- **依赖版本策略**：示例依赖与主站一样锁精确版本（FR-023），但**不进入** `AGENTS.md §2.1` 锁定表、不进根 `go.mod`——它们是示例自有清单的一部分，升级节奏与主站解耦。
- **文档收敛的边界**：`docs/integration-guide.md` 只把「§9 三语言完整示例」改为索引与差异说明，协议与端点事实（§1–§8、§10–§13）仍是权威内容，不得因收敛而删减。
