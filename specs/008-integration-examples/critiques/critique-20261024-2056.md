### Architecture Soundness

| ID | Severity | Finding | Suggestion |

| E11 | 💡 | **A15（降级断言）目前没有可执行的注入点**。`userinfo` 地址来自发现文档，示例没有覆盖入口；契约又允许 A15 `[SKIP]`，实际结果很可能是「SC-009 永远没被自动验证」。 | 在契约与示例里加一个**仅调试用**的覆盖变量 `SSO_USERINFO_URL_OVERRIDE`（默认空=用发现值），A15 用它指向 `http://127.0.0.1:1/userinfo`，即可稳定断言 200 + `degraded=["userinfo"]`；实现成本约 3 行，同时把这个变量写进 README 的「调试用」小节。 |
| E12 | 💡 | **A11 用「IdP 的 `sid` 值不变」做断言过强**。若 IdP 在授权过程中刷新会话（如 `auth_time` 更新或轮换 sid），断言会误报失败，掩盖真正的 cookie 冲突。 | 改为两个更贴事实的断言：① 门户（`localhost:5173`）在示例登录前后 `/api/v1/me` 均 200（会话仍有效）；② 示例进程未写出名为 `sid` 的 cookie（抓 `Set-Cookie` 头断言前缀）。前者是结果，后者是原因，|两者都比字节比对稳。 |
| E13 | 💡 | **Java/Python 的会话 cookie 默认名都不是契约要求的名字**：Spring Boot 默认 `JSESSIONID`、Starlette `SessionMiddleware` 默认 `session`。契约只写"必须是 `sid_java`/`sid_py`"，实现时极易漏改，而漏改的后果正是 E1 那类事故。 | 在 plan 的结构注释与 tasks 里显式点名配置项：Java `server.servlet.session.cookie.name: sid_java`；Python `SessionMiddleware(..., session_cookie="sid_py")`；Go 直接 `SetCookie("sid_go", ...)`。契约表下方加一句「默认名需显式改写，不是改个变量名那么简单」。 |
