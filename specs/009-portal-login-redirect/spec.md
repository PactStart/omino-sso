# Feature Specification: 未登录 OIDC 授权统一跳转门户登录页

**Feature Branch**: `009-portal-login-redirect`

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: "未登录的 OIDC 授权统一跳转到门户登录页（PORTAL_LOGIN_URL），登录完成后回到 sso /login?id= 完成授权并 302 回 SP；dev 与 test/prod 都启用，IdP 模板页降级保留；禁止 SameSite=Strict；新增 loop guard；补 SSO 快捷完成的审计事件；examples e2e 增加 portal 前置与 A18/A19"

## Clarifications

### Session 2026-10-25

- Q: 生产环境未配置门户登录页地址时，统一身份应当启动失败还是回落到内置登录页？ → A: prod 必填，缺失即启动失败；dev/test 允许缺失并回落到内置登录页。
- Q: 端到端脚本里断言 A18/A19 时，门户登录页地址从哪里来？ → A: 由环境变量 `E2E_PORTAL_LOGIN_URL` 显式提供期望值（默认 `http://localhost:5173/login`），A18 硬断言跳转目标，缺失或不一致即以前置条件不满足退出，不静默跳过。
- Q: 用户被统一身份送到门户登录页时，页面上的"登录后返回…"提示该显示什么？ → A: 统一身份随回跳目标附带来源应用显示名，门户显示"登录后返回 <应用名>"；附加信息缺失或非法时退回默认文案，不中断回跳。
- Q: 循环防护触发、回落到内置登录页时，用户和运维应该看到什么提示？ → A: 页面追加一行可读说明（"登录状态未能在跳转中延续，请在此直接登录"），服务端记录一次降级日志（含原因分类、不含凭据）；不新增审计事件。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 未登录的接入方访问由门户登录页接管（Priority: P1）

员工从任意接入系统打开页面时，若尚未登录统一身份，浏览器不再停在身份提供方自己的一张内置表单页上，而是被送到统一门户的登录页。用户在门户登录页完成登录（账号密码、验证码或 MFA 任一路径）后，浏览器自动回到统一身份完成本次授权，再由统一身份 302 回到最初访问的接入系统，用户直接落在目标页面。如果回跳回来后统一身份仍然认不出会话，浏览器会退回到内置登录页，而不是在两个页面之间来回弹跳。

**Why this priority**：这是本特性的全部用户价值所在——统一入口、统一品牌、登录相关能力（验证码、找回密码、MFA、锁定提示）只在门户维护一份；同时它直接决定"用户能不能进得去"，必须先成立。

**Independent Test**：清空浏览器全部 cookie，直接打开任一接入系统的受保护地址，观察浏览器落点、完成登录后的返回路径，以及最终落在接入系统的页面。

**Acceptance Scenarios**：

1. **Given** 用户未登录且统一身份已配置门户登录页地址，**When** 用户打开接入系统的受保护页面（触发授权请求），**Then** 浏览器落在配置的门户登录页上，而不是统一身份的内置表单页，且页面提示"登录后返回 <来源应用名>"（看不到 `/login` 这类技术路径）。
2. **Given** 用户停在门户登录页，**When** 用户用账号密码完成登录，**Then** 浏览器自动回到统一身份完成本次授权并 302 到接入系统回调，全程不需要第二次输入凭据，接入系统显示为已登录。
3. **Given** 用户在门户登录页触发了 MFA 第二步，**When** 用户提交正确的动态码，**Then** 结果与场景 2 一致（同一条回跳链路、无需再做额外操作）。
4. **Given** 统一身份未配置门户登录页地址（仅 dev/test 允许），**When** 用户打开接入系统的受保护页面，**Then** 浏览器落在统一身份的内置登录页，且该页可以正常完成登录（与改造前一致）。
5. **Given** 用户从门户回跳回来后统一身份仍然没有有效会话（cookie 未送达、已过期或被清除），**When** 浏览器重新打开统一身份的登录入口，**Then** 统一身份在这一次回跳内改为展示内置登录页（页面上有一行说明"登录状态未能在跳转中延续，请在此直接登录"），不得再次把浏览器送回门户；服务端同时留下一条可定位的降级记录。
6. **Given** 用户已在统一身份登录（会话有效），**When** 用户打开接入系统的受保护页面，**Then** 不经过门户、不出现任何登录页，授权直接完成并回到接入系统。
7. **Given** 授权请求已过期或不存在，**When** 用户打开统一身份的登录入口，**Then** 返回可读的错误提示（沿用现状行为），不得跳转门户。

### User Story 2 - SSO 快捷完成在审计中可追溯（Priority: P1）

管理员在审计日志中能看到"用户凭既有会话直接完成某应用授权"的记录，并与"输入密码登录成功"区分开，可按来源与时间排查。

**Why this priority**：凭既有会话直接完成授权目前不留任何痕迹，安全审计无法回答"这次访问究竟是新登录还是会话复用"；而本特性会让这种"无输入即完成"的路径成为主路径，留痕属于安全底线。

**Independent Test**：用已登录的浏览器完成一次接入系统授权，查询审计日志，应出现一条可与其他登录事件区分的事件；再执行一次表单登录，两类事件应分别可见。

**Acceptance Scenarios**：

1. **Given** 用户已有有效会话，**When** 用户凭该会话完成一次接入系统授权，**Then** 审计日志新增 1 条"会话复用完成授权"事件，包含用户、应用、结果、发生时间与来源信息。
2. **Given** 同一用户在短时间内连续完成两次授权，**When** 查询审计日志，**Then** 两条事件各自独立存在，不合并、不丢失。
3. **Given** 用户改用表单输入账号密码完成登录，**When** 查询审计日志，**Then** 原有"登录成功"事件照旧记录，既不消失也不因新增事件而重复计数。
4. **Given** 管理员在审计页按事件类型筛选，**When** 选择"会话复用完成授权"，**Then** 只能筛出该类事件，且分页/导出行为与既有事件一致。

### User Story 3 - 三套环境行为一致且配置错误立即暴露（Priority: P2）

部署方在 dev / test / prod 用同一套行为：只要提供了门户登录页地址就生效，不做环境特判；同时会话 cookie 的属性与地址格式被启动校验守住，配错直接启动失败而不是"上线后绕圈"。

**Why this priority**：这类"开发环境走 A 分支、生产走 B 分支"的改造，最容易在测试环境全绿、生产出现来回跳转；但相对核心链路它属于保障性需求，不阻塞可用性。

**Independent Test**：分别在 dev 与 test/prod 配置下启动，重复同一操作并比对结果；再故意写入错误配置，观察启动行为。

**Acceptance Scenarios**：

1. **Given** 运行在 dev 环境且已配置门户登录页地址，**When** 用户未登录访问接入系统，**Then** 行为与 test/prod 完全一致（跳门户），不存在"仅生产启用"的分支。
2. **Given** 会话 cookie 被配置为 `SameSite=Strict`，**When** 启动统一身份，**Then** 启动失败并以非零码退出，错误信息指明该配置项（跨站跳转链上 Strict 会导致会话不被携带，形成"刚登录又被要求登录"）。
3. **Given** 门户登录页地址不是带协议与主机的绝对地址，**When** 启动统一身份，**Then** 启动失败并指明该配置项；test/prod 下还要求必须为 https。
4. **Given** 门户与统一身份同属一个主域，**When** 用户走完整链路，**Then** 会话 cookie 在门户与统一身份之间被正常携带，无需放宽为无 SameSite 限制。
5. **Given** 运维在 dev/test 清空门户登录页地址配置，**When** 重启统一身份，**Then** 系统回到改造前行为（内置登录页），无需回滚版本。
6. **Given** 运行在 prod 且门户登录页地址缺失，**When** 启动统一身份，**Then** 启动失败并以非零码退出、指明该配置项（prod 回滚只能回退到改造前版本，不允许"清空配置继续跑"）。

---

### User Story 4 - 端到端验证覆盖新链路（Priority: P2）

维护者执行接入示例的端到端验证时，除既有断言外还能验证"未登录跳门户"与"循环防护降级"，并且在开始前用"等同于门户登录"的方式准备好会话，使既有断言在新的默认行为下依然成立。

**Why this priority**：没有可重复的自动化断言，新链路只能靠人工点浏览器验证，回归成本会立刻反噬；但它不改变最终用户体验，故排在核心链路之后。

**Independent Test**：在本地已启动统一身份（同时配置了门户登录页地址）的前提下执行一次端到端命令，观察逐项断言与退出码。

**Acceptance Scenarios**：

1. **Given** 统一身份已运行且已配置门户登录页地址，**When** 执行接入示例的端到端命令，**Then** 命令先完成"门户前置"（以与门户登录页相同的登录能力建立会话），随后既有 A0–A17 断言全部通过。
2. **Given** 浏览器没有任何统一身份会话，**When** 从接入示例发起登录，**Then** 新增断言 A18 判定浏览器被送到配置的门户登录页（且携带的回跳目标指向统一身份的登录入口），而不是内置表单页。
3. **Given** 浏览器携带"已从门户回跳"标记但仍无会话，**When** 打开统一身份登录入口，**Then** 新增断言 A19 判定展示的是内置登录页（含可提交表单与降级说明文案），并且该页提交后仍能完成登录并 302 回示例回调。
4. **Given** 前置条件不满足（`E2E_PORTAL_LOGIN_URL` 未提供任何期望值模板、或被验证的统一身份实际跳转与期望地址不一致），**When** 执行端到端命令，**Then** 以"前置条件不满足"的退出码结束并指明原因，不得静默跳过 A18/A19。

### Edge Cases

- **门户不可达**：门户站点宕机或回跳地址 404 时，用户停在门户的错误页；统一身份不参与后续流程，因此不存在跳转循环——但需要在错误提示层面让用户知道"是门户不可用"而非"凭据错误"。
- **门户丢弃回跳目标**：若门户的登录后回跳白名单不包含统一身份登录域，用户登录后会停在门户首页，表现为"登录成功却回不到接入系统"。这是必须在交付前被断言拦住的缺陷，不是可选优化。
- **会话 cookie 域配置错误**：cookie 写成 host-only 或落到错误主域时，回跳后统一身份仍认不出会话；此时循环防护必须在一次回跳内降级到内置登录页，不能靠"再跳一次就好"。
- **用户手动改写/删除回跳标记**：视为一次新的访问，可能再次被送去门户；这属于用户的主动行为，可接受，但同一授权请求不得因此产生多于一次的自动跳转。
- **授权请求过期后从门户回跳**：**不得**沿用裸 400 文本。用户可能因找回密码、绑定 MFA 在门户停留超过授权请求有效期，回到统一身份时请求已失效；此时必须给出可继续的路径（引导返回接入系统重新发起授权，或提供可点击的重新登录入口），不得停在无出路的错误文本上、不得跳门户、不得 500。
- **门户登录页地址带查询串或尾斜杠**：拼接回跳信息时不得破坏原地址语义（路径与已有查询串都要保留），否则门户会 404。
- **多标签页并发发起授权**：每个授权请求独立完成，互不覆盖；同一授权请求只能被消费一次（不得产生第二个授权码）。
- **重复提交**：用户在门户或内置页连点登录，只允许产生一次成功授权与一条"会话复用"事件。
- **回跳参数被篡改**：外部把回跳目标改成站外地址时，门户侧必须拒绝（落回门户首页），统一身份自身不得成为开放重定向的帮凶。
- **已登录用户携带过期授权请求**：给出"请求已过期"提示，不因已登录而静默吞掉错误。
- **来源应用名缺失或被篡改**：门户登录页退回默认文案（不显示来源信息），登录与回跳流程不受影响；不得把外部传入的任意文本直接渲染成可执行内容。
- **来源应用名过长**：门户侧截断展示，不撑破版面，也不影响回跳地址本身。
- **用户在门户放弃登录**：用户关掉门户标签或回门户首页后，再点接入系统的登录入口会再次被送到门户登录页。这是预期行为（不是缺陷），但门户登录页需有足够说明（"登录后返回 <应用名>"），避免体感为"一直在跳"。
- **回跳标记被剥离**：若浏览器/扩展剥离了查询参数导致标记丢失，最坏结果是"多一次门户往返"而非死循环——每次门户跳转都由统一身份重新生成完整地址，标记随之恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：用户未登录时访问任意接入系统的授权端点，统一身份 MUST 以 302 把浏览器送到配置的门户登录页地址，而不是直接展示内置表单页。
- **FR-002**：门户登录页地址 MUST 由配置提供（沿用前端既有命名 `PORTAL_LOGIN_URL`，值为门户登录页的绝对地址）；该行为 MUST 在 dev / test / prod 一致生效，禁止按环境名开关。
- **FR-003**：跳转 MUST 携带由统一身份生成的回跳目标，指向"统一身份登录入口 + 本次授权请求标识"；回跳目标不得由外部请求参数直接指定（防开放重定向）。
- **FR-004**：从门户回跳后若存在有效会话，统一身份 MUST 立即完成本次授权并以 302 返回接入系统回调，用户不得被要求二次输入凭据（启用 MFA 的用户同样只需在门户侧完成一次 MFA）。
- **FR-005**：门户登录页地址的**必填性** MUST 按环境区分：prod 必填，缺失 MUST 启动失败并以非零码退出、错误信息指明该配置项；dev/test 允许缺失，此时 MUST 保持改造前行为（展示内置登录页并可完成登录，不得报错或白屏）。地址的格式与协议约束统一见 FR-014（本条不重复规定 https）。
- **FR-006**：循环防护：当浏览器带"已从门户回跳"的标记到达登录入口却仍无有效会话时，统一身份 MUST 停止向门户跳转，改为展示内置登录页；同一授权请求自动跳门户的次数上限为 1。
- **FR-007**：循环防护标记 MUST 由统一身份签发并与本次授权请求绑定，不得携带任何凭据信息，也不得因刷新/后退被无限重放而重新触发门户跳转。
- **FR-008**：内置登录页 MUST 保留完整能力（账号密码、MFA 第二步、锁定/停用/错误提示、登录成功后的 302 回跳），作为降级与循环兜底路径长期保留。
- **FR-009**：已登录用户访问授权端点 MUST 直接完成授权：不经过门户、不出现登录页、不产生额外的用户交互。
- **FR-010**：每次"凭既有会话直接完成授权" MUST 产生一条审计事件，包含用户、应用、结果、发生时间与来源信息，且事件类型可与"密码登录成功"区分。
- **FR-011**：新增审计事件类型 MUST 登记到项目的事件类型注册表，并能被审计页的事件类型筛选命中；不得用"密码登录成功"顶替而不做区分。
- **FR-012**：会话 cookie 的 SameSite MUST 为 `Lax`；配置为 `Strict` 时 MUST 启动失败并指明该配置项（Strict 会让跨站跳转链上的会话不被携带，导致登录后再次要求登录）。
- **FR-013**：门户登录页 MUST 只回跳到白名单内的目标（门户自身、管理后台、统一身份登录域）；白名单外的目标 MUST 被丢弃并落回门户默认页，不得整页跳转。
- **FR-014**：门户登录页地址在 test/prod MUST 为 https 绝对地址；非法值 MUST 启动失败并指明配置项（dev 同样校验绝对地址格式，仅放宽 https 要求）。
- **FR-015**：接入示例的端到端验证 MUST 增加"门户前置"步骤与 A18/A19 两条断言，且既有 A0–A17 断言在新行为下仍全部通过；期望的门户登录页地址 MUST 由显式配置（`E2E_PORTAL_LOGIN_URL`，默认 `http://localhost:5173/login`）提供，A18 MUST 硬断言跳转目标与该地址一致，地址缺失或与被测实例实际行为不符时 MUST 以"前置条件不满足"退出（非 0），不得降级为跳过。
- **FR-016**：部署文档与接入文档 MUST 记录新增配置项、行为变化（未登录落点由内置页改为门户登录页）以及回滚方式：dev/test 清空该配置即回到内置页，prod 因必填只能回退到改造前版本。
- **FR-017**：管理后台既有的"会话失效跳门户登录页"策略 MUST 保持不变；本特性不改变管理后台前端行为。
- **FR-018**：登出链路 MUST 保持不变；登出后再次访问接入系统时，用户应重新被送到门户登录页。
- **FR-019**：从统一身份跳入门户登录页时，门户 MUST 显示"登录后返回 <来源应用显示名>"（来源信息由统一身份随回跳目标附带）；该附加信息缺失、被篡改或不在白名单内时，门户 MUST 退回默认文案并继续正常登录，不得报错或中断回跳。
- **FR-020**：循环防护触发时，降级页 MUST 追加一行可读说明（含义为"登录状态未能在跳转中延续，请在此直接登录"），服务端 MUST 记录一条可定位的降级记录（含原因分类、不含任何凭据）；该降级 MUST NOT 产生新的审计事件类型，以免污染登录失败统计。
- **FR-021**：从门户回跳时若授权请求已失效（含超过有效期），统一身份 MUST 给出可继续的操作路径（返回接入系统重新发起授权 / 可点击的重新登录入口），不得停留在无出路的纯文本错误页；该分支 MUST 与"无标记的请求失效"区分处理，后者保持现有 400 行为。
- **FR-022**：包含来源应用名的回跳地址 MUST NOT 被第三方站点通过 `Referer` 获取——门户侧对含该参数的页面 MUST 采用同源 `Referrer-Policy`；该地址仅用于本次跳转，不得写入日志或埋点。

### Key Entities *(include if feature involves data)*

- **授权请求**：一次待完成的 OIDC 授权上下文（应用、回调地址、请求范围、请求标识、有效期）。本特性关注它的生命周期与"是否已尝试过门户跳转"这一状态。
- **会话**：用户在统一身份的有效登录状态，通过仅服务端可见的 cookie 承载；本特性关注它在门户与统一身份之间的携带情况，以及"无会话"时的降级判定。
- **门户登录页地址（配置项）**：门户登录页的绝对地址，决定未登录用户的落点；prod 必填，dev/test 允许为空（为空即回落到内置登录页）。
- **回跳目标**：统一身份生成、门户登录页消费的"登录后回到哪里"信息；必须在门户侧通过白名单校验。
- **审计事件**：记录"凭既有会话完成授权"的安全事件，含用户、应用、结果、时间与来源信息，类型独立于"登录成功"。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：未登录用户从接入系统发起访问时，100% 落在门户登录页（在配置了门户地址的环境中，端到端断言 A18 通过）。
- **SC-002**：分两段可测口径（均不含用户输入凭据的时间）：① 用户在门户登录页点击"登录"成功后，到落在接入系统页面 ≤ 3 秒、浏览器跳转 ≤ 2 次、0 次二次凭据输入；② 用户已有会话时从接入系统发起，到落在接入系统页面 ≤ 2 秒、0 次输入。
- **SC-003**：在"回跳后仍无会话"的构造场景下，浏览器在 1 次回跳内落到内置登录页（页面含降级说明、服务端有 1 条可定位的降级记录）；同一授权请求的自动跳门户次数恰为 1，死循环次数为 0（端到端断言 A19 通过）。
- **SC-004**：审计事件既不合并也不丢失——① 同一会话连续 2 次"凭既有会话完成授权"产生 2 条独立事件（单测可验）；② 连续 10 次操作后审计仍为 10 条（端到端观察）；③ 管理后台可按事件类型单独筛出该批事件。
- **SC-005**：`SameSite=Strict`、非法门户地址、prod 缺失门户地址三类配置错误，各产生 1 次启动失败（非零退出 + 明确变量名），静默降级次数为 0。
- **SC-006**：既有质量门禁（单元测试、构建、注册表一致性检查、四域端到端验证）全部通过；三语言接入示例端到端 A0–A19 全绿，单次执行耗时不超过改造前的 120%。
- **SC-007**：dev/test 下仅清空门户登录页地址并重启即可恢复到改造前行为（一次验证确认）；prod 下回滚到改造前版本后启动成功，且改造版本在缺失该配置时 0 次启动成功。
- **SC-008**：从接入系统跳到门户登录页的 100% 情况都显示来源应用名（A18 断言页面或回跳参数中带应用名），0 次向用户展示 `/login` 这类技术路径；来源信息被篡改时 0 次登录失败。
- **SC-009**：上线后可持续观测三项信号——① `sso_login_success` 与 `login_success` 的日条数比（判断主路径是否真的走门户）；② 登录入口"请求已失效"响应的占比（目标 < 1%，超出指向有效期或配置问题）；③ 日均被送到门户登录页 ≥ 3 次的账号数（异常升高指向标记丢失或门户回跳失败）。

## Assumptions

- **A1**：门户登录页已存在且已支持"登录后回跳到给定目标"（`?next=` 机制由既有门户交付），本特性只扩展其可回跳白名单并新增统一身份侧配置，不重写门户登录页。
- **A2**："门户登录"指门户登录页既有的登录能力（密码、邮箱验证码、短信验证码 + MFA），本特性不新增或变更任何登录方式。
- **A3**：门户、管理后台、管理 API、统一身份四域同属一个主域（同站），因此 `SameSite=Lax` 足以完成跨子域整页跳转；本特性不引入 `SameSite=None`，也不引入跨域请求。
- **A4**：循环防护采用"一次回跳即降级"的保守策略，不区分原因（cookie 未送达、会话过期、用户清除）；理由是无法在回跳点上可靠区分，而误判的代价（死循环）高于多展示一次内置页。
- **A5**：审计采用新增独立事件类型（不复用"登录成功"），事件详情记录认证入口（门户回跳 / 内置页），以便与密码登录的统计口径分离。
- **A6**：接入示例的端到端验证不引入浏览器自动化；"门户前置"通过"与门户登录页相同的后端登录能力"建立会话，等价于"用户已在门户登录"，从而让既有断言在默认跳门户的前提下仍然成立。
- **A7**：内置登录页长期保留，不因主路径改为门户而删除；它同时承担"未配置门户地址"与"循环降级"两种场景。
- **A8**：门户登录页地址的取值形如 `https://portal.example.com/login`；它与统一身份同主域，因此回跳不需要额外信任配置。
- **A9**：现有接入系统无需任何改动即可受益；它们继续按 OIDC 标准接入，感知不到登录页落点的变化。
- **A10**：端到端验证默认假设"被测统一身份跑在 dev 配置、门户登录页在 `http://localhost:5173/login`"；换环境时通过 `E2E_PORTAL_LOGIN_URL` 覆盖期望值即可，脚本不试图改写被测进程的配置。
- **A11**：本特性的动因是"收敛两套登录 UI"的主动治理（005/007 交付后，内置页与门户登录页的能力需双份维护），不是由用户投诉驱动，故不附外部证据。
- **A12**：本特性要求统一身份**单副本部署或会话粘性（sticky）路由**。待认证授权请求保存在进程内存（既有设计），门户往返把其存活窗口从毫秒级拉长到分钟级；多副本且无粘性时，回跳可能落到不持有该请求的副本，表现为"登录请求已过期"。

## Out of Scope

- 门户登录页的视觉改版或交互重构（只在回跳白名单上做必要扩展）。
- 跨 registrable domain 的单点登录（需要 `SameSite=None` + CORS，属 007 已划定的边界之外）。
- 无密码登录、社交登录、Passkey 等新增认证方式。
- 引入浏览器自动化测试框架替代现有的无头端到端验证。
- 审计页面的报表/图表改版（仅新增事件类型的可见与可筛选）。
