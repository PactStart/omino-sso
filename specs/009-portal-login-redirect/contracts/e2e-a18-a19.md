# Contract: 接入示例端到端验证的门户前置 + A18/A19

**Feature**: `009-portal-login-redirect`

脚本：`scripts/e2e/examples.sh`（无头 HTTP 驱动，不启浏览器）。本特性把断言清单从 **A0–A17** 扩到 **A0–A19**，并新增一个**非断言**的门户前置步骤。

## 1. 新增环境变量

| 变量 | 默认 | 语义 |
|---|---|---|
| `E2E_PORTAL_LOGIN_URL` | `http://localhost:5173/login` | 期望的门户登录页地址；A18 用它做**硬断言**（scheme + host + path 全等） |

前置约束：被测 IdP 的 `PORTAL_LOGIN_URL` 必须与该值一致。不一致或 IdP 未配置（实际仍落 `/login?id=`）→ **退出码 2**，输出「前置不满足：IdP 未按门户跳转（期望 <VALUE>，实际 <LOCATION>）」。

## 2. 门户前置（Portal Pre-step，无断言编号）

**位置**：A2（专用账号就绪）之后、A3（示例启动）之前。

**动作**：用**与门户登录页相同的后端登录能力**建立 IdP 会话，模拟「用户已在门户登录」：

```text
POST $E2E_API/api/v1/auth/login   {"username":$E2E_EXAMPLE_USER,"password":$E2E_EXAMPLE_PASS}
→ cookie jar: $WORK/portal.cookie（sid）
```

**判定**：

- `200` 且 jar 内出现 `sid` → 通过，日志打印「门户前置：已建立 IdP 会话」；
- 返回 `mfaRequired` / 非 200 → 退出码 2（示例账号不得启用 MFA，见 008 契约）；
- 网络错误 → 退出码 2（不重试登录：会累加失败计数）。

**对既有断言的影响**：A4–A6 把 `$WORK/portal.cookie` 复制为各自语言 jar 后再 `drive_login`，因此三个示例走的是**SSO 快捷完成**路径（`LOGIN_SAW_IDP_FORM=0`）；表单 POST 路径由 A19 覆盖。A8/A9/A10/A12/A13/A15/A16/A17 语义不变。

**语义与计时口径变更（必须写进脚本注释）**：

| 项 | 变更前（008） | 变更后（009） |
|---|---|---|
| A4–A6 语义 | 登录闭环（含表单 POST + 密码校验） | **SSO 闭环**（凭既有会话完成授权） |
| SC-001 计时 | 进程启动 → 首次 `/api/me` 200（含一次 argon2 校验） | 同口径但**不再含密码校验**，数值会变快；**禁止与 008 数据直接比较**，自 2026-10-25 起重新建立基线 |
| 表单 POST 覆盖 | 三语言各一次 | A19 对 go / java / python 各一次（见 §4） |

## 3. A18：未登录授权落到门户登录页

**前置**：无会话的空 jar（A12/A13 已登出并清空）。

**动作**：

```text
GET $E2E_ISSUER/oauth2/authorize?client_id=<go>&response_type=code&scope=openid profile email
    &redirect_uri=<go 回调>&state=a18&code_challenge=<S256>&code_challenge_method=S256
（不跟随跳转，只读 Location）
```

**断言（全部满足才算 PASS）**：

1. 状态码 `302`；
2. `Location` 的 scheme+host+path **等于** `$E2E_PORTAL_LOGIN_URL`；
3. `Location` 的 `next` 参数（解码一次）匹配 `^<E2E_ISSUER>/login\?id=[^&]+&portal=1$`；
4. `Location` 的 `app` 参数非空；
5. `Location` **不**等于 `<E2E_ISSUER>/login?id=…`（反证：没有退回内置页）。

**失败信息**：打印实际 `Location` 与被测 IdP 的期望值，直接指向「`PORTAL_LOGIN_URL` 未配置 / 与脚本不一致」。

**计时口径（SC-002，必须固定，否则不可比）**：

| 段落 | 起点 | 终点 | 目标 | 采集处 |
|---|---|---|---|---|
| 有会话直达 | 发出 `GET /oauth2/authorize` | 收到指向 SP 回调的 `302` | ≤ 2 秒 | A4–A6（每语言各一次） |
| 门户登录后回跳 | 在门户点击「登录」并收到登录接口 200 | 收到指向 SP 回调的 `302` | ≤ 3 秒、跳转 ≤ 2 次 | `run.sh` 场景 7 |

两侧都**不含用户输入凭据的时间**；统一用 `date +%s.%N` 或 `curl -w '%{time_total}'` 采集，结果打印到断言日志，便于跨版本对比（008 的 SC-001 基线自 2026-10-25 起作废）。

## 4. A19：loop guard 降级 + 内置页仍可完成登录

**前置**：沿用 A18 的 `next`（含 `portal=1`），空 jar。

**动作与断言**：

1. `GET <next>`（空 jar）→ **`200`**（不是 302），
2. 响应体含 `<form` 与降级说明关键词（`未能在跳转中延续`），
3. 提取表单里的 `id`（或直接用 A18 已知的 `id`），`POST $E2E_ISSUER/login`（`id` + 示例账号密码）→ `302`，
4. `Location` 指向 `/oauth2/authorize/callback`；跟随一跳后 `Location` 以 `<go 回调>?code=` 开头，
5. 拿到的 `code` 可换取 token（`200`，`access_token` 非空）——证明降级页确实能完成授权，而不只是"看起来像表单"。

> A19 的第 3–5 步同时承担「内置登录页未被本次改动破坏」的回归职责（FR-008）。

**三语言补偿**：第 3–4 步对 java / python 客户端再各跑一次（各自 `client_id` + 回调 + PKCE，仅断言 `302` 到 `<lang 回调>?code=`，不重复换 token）。理由：A4–A6 改为 SSO 起步后，若只保留 go 一条表单路径，三语言覆盖会退化成单语言——而表单 POST 与 `Set-Cookie` 是唯一与客户端语言无关、但必须逐语言验证回跳地址的环节。

**过期分支（FR-021）不在此断言**：A19 的 `next` 必然对应一个仍有效的请求；过期分支由四域 e2e 通过"构造已过期 id + `portal=1`"覆盖，或由 Go 单测覆盖（`decideStep` 的 `StepRequestExpired`）。

## 6. 退出码

| 码 | 含义 |
|---|---|
| 0 | 全绿（含 A18/A19） |
| 1 | 有断言失败 |
| 2 | 前置条件不满足（缺工具链 / IdP 不可达 / 门户地址不一致 / 示例账号需 MFA / 端口占用）——此时尚未开始断言或已明确中止 |

**禁止**：把 A18/A19 在「IdP 未配置门户」时标记为 SKIP 并仍然以 0 退出（spec US4 场景 4）。

## 7. 附：四域脚本（`scripts/e2e/run.sh`）的对应调整

`make e2e` 用的是真实四域 HTTPS（自签证书 + nginx），在那里验证跨子域 cookie 与 loop guard 更真实：

- `start_backend` 增加 `PORTAL_LOGIN_URL="https://portal.$DOMAIN:$HOST_PORT/login"`（`APP_ENV=test` 下必须 https）；
- 场景 7 第一步的断言改为「`/oauth2/authorize` → 302 到门户登录页，`next` 指回 sso 域登录入口」，并追加「门户登录页可达（`200`）」；
- 场景 7 的登录步骤改为「api 域 `POST /api/v1/auth/login` 建立共享会话 → 访问 `next` → 完成授权」，即真实用户路径；
- 新增 loop guard 断言：以空 jar 访问 `next`（带 `portal=1`）→ `200` HTML 内置页（不 302 回门户）。
